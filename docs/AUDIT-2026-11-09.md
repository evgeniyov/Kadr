# Kadr audit, 9 November 2026

## Scope and result

The audit covered app behavior, capture and recording sessions, the editors, saving and recovery, interprocess communication (IPC) limits, dependencies, packaging, and possible performance and interface improvements. The project fixed confirmed defects locally. This work added no major interface changes or product features.

The audit started at commit `7c8a889` on `main`, version 1.0.10. Version 1.0.11 includes the fixes. See the [changelog](../CHANGELOG.md).

The checks used synthetic files, separate temporary profiles, mock devices, and deliberately introduced errors. The audit used no personal images or recordings and did not record the desktop or microphone.

## Fixes

| Area | Defect and fix |
|---|---|
| Image saves | Three concurrent saves with the same filename template produced one file. One automatic save queue per actual directory now preserves all three files. A failed job leaves the next job free to run. Automatic capture saves use the same atomic write. |
| Library recovery after a crash | When Kadr wrote a PNG before its delayed index write, a valid old index prevented Kadr from recovering the image. Kadr now reconciles unindexed PNGs on every start. |
| Library redaction | If a new thumbnail failed to save, the old one remained visible. Kadr now removes the old thumbnail before replacing the pixels. If the write fails, Kadr rebuilds the missing thumbnail from the current PNG at the next start. It also clears the old text recognition results. |
| Corrupt library metadata | An independent review found that recovery could assign the original PNG's name to a thumbnail. The index now accepts only the item's own `id.png` and `id.thumb.jpg`. Kadr keeps corrupt indexes separately and recovers the originals. |
| Search | A late response could redraw results and change the selection after the query changed. Kadr checks the query generation and current text. It shows errors for the current query. |
| Keyboard shortcuts | Closing settings or crashing its window while assigning a shortcut left global shortcuts off. Kadr ties the suspension to the specific `webContents` and releases it when that instance exits. The fix removes stale conflict statuses and handles asynchronous action errors. |
| Unsaved changes | Backdrop changes and typing did not always mark the document as unsaved before the window closed. They now do so immediately. Save and Save As work while the text field has focus, including with the Russian keyboard layout. |
| Background removal | A late result could replace newer edits. The editor checks for changes after encoding, after the native request, after decoding, and before trying the fallback. It releases the ImageBitmap. |
| Text redaction and recognition | Replacing base pixels or using Undo could leave stale coordinates from text recognition. The editor ties the cache and requests to the base image or object and discards stale responses. It covers the entire selection until it gets a new result. |
| Copy, Save, and GIF | A late Copy could put an older capture back in the library after a newer Save. The editor runs both operations in order. Both frames of a before-and-after GIF use the same revision. |
| Selection outlines | The editor checked the 250000-segment limit after building the full Path2D. It now stops as soon as it exceeds the limit and reuses the previous outline. On a synthetic 1024² mask, it builds 250001 segments instead of 1048576. |
| Selection overlay | Closing the overlay, crashing its renderer, or failing to load left capture busy. Kadr now clears pending work and discards late loads from canceled windows. A change to the display layout cancels selections based on the old coordinates. |
| Scrolling capture | Kadr now applies timeouts, ties requests to their session, removes IPC listeners, and handles repeated Finish requests and panel crashes. A canceled session cannot affect the next one. |
| Displays | Screenshot, scrolling capture, and recording now reject a source with a known, mismatched `display_id`. Screenshots and recordings still accept complete older source lists with no IDs. Those lists depend on the physical order of the displays. |
| Scrolling screenshot height | A repeated footer made a 150 px limit produce a 160 px image. Kadr now applies the limit to the first frame too. If that frame fills the image, Kadr skips scrolling. |
| Recording cancellation | Canceling during source lookup, permission checks, opening the raw file or audio track, or starting native audio could leave a resource open or start a recording later. The same session now manages setup and cleanup. A new recording waits for that session to finish. |
| Worker startup failure | An independent review found an unhandled rejection when sending a message threw synchronously. The wait for `started` now ends correctly in that case. |
| Video rotation | Imported videos rotated by 90° or 270° now have dimensions that match the preview and crop. A 180° rotation leaves the dimensions unchanged. The tests used FFmpeg. |
| Video editor operations | An import could replace the file after an export started. Import, delete, and export now reserve the document before the first `await`. The editor discards late results after its window closes. |
| Recording recovery | If Kadr cannot inspect or deliver a recording, it keeps the raw file, separate audio, and completed intermediate file. Kadr removes ordinary temporary files after a complete save. If output validation fails, Kadr reports that error instead of `EMPTY`. Recovery keeps previous failed output files. |
| Dependencies | Updated Electron from 44.4.4 to 44.10.2 and electron-builder from 26.15.3 to 26.18.0. Updated fast-uri and undici. The minimatch 11.0.1 fix applies only to vulnerable versions 7 through 10. Dependent tools keep the callable APIs from versions 3 and 5. |

The recording recovery suite passed 9/9 scenarios. It checked cleanup after a successful save, failures when reading, writing, or mixing audio, and a partial write of the first chunk when the disk ran out of space (`ENOSPC`). An independent review found that the byte counter could read zero even when the file contained part of the first chunk. Kadr now keeps that file.

## Checks and results

- The first `npm test` run had 93 tests. The final run passed 174/174 with no failures or skips, an increase of 81 tests. Intermediate runs passed 165/165 and 173/173. The final run included the partial write with `ENOSPC`.
- `npm run test:electron` passed on Electron 44.10.2. It checked running renderers, PNG export, IPC and camera limits, unsaved backdrop and text changes, Undo, the preloaded editor before the PNG existed, synthetic video in the scrolling capture worker, video playback, and byte-range seeking.
- `node --test native/test/window-filter.test.js` passed 3/3 with a mock helper and display coordinates.
- The Swift helper passed 6/6 checks with synthetic images. The checks covered capabilities, startup, Russian and English text recognition, QR codes, background removal, and input errors. The test filter excluded capture, sound, and scrolling.
- The main suite used FFmpeg to test audio tracks and codecs, export cancellation, video rotated by 90°, 180°, or 270°, cropping, and resizing. All passed.
- The native build script confirmed that the existing universal helper was up to date. It reused that build. The audit made no Swift code changes.
- The full `npm audit` found 0 known vulnerabilities. At the start, it reported 9 affected packages, with 2 high and 7 moderate. Run the audit without `--omit=dev` because the app ships Electron, which is a `devDependency`.
- `npm ls` confirmed that dependencies were consistent. Separate checks covered FileMatcher include, exclude, partial, and extglob matching, and synthetic mergeASARs allow and deny cases with the new minimatch. The older glob, asar, and filelist packages retained the old API.
- electron-builder built an arm64 macOS test package at `<temp>/kadr-audit-package/mac-arm64/Kadr.app` with ad hoc signing. `codesign --verify --deep --strict` passed. All 130 `src` files matched the working tree. The package included the native helper and Russian and English tessdata. The project kept this test package unpublished and did not notarize it.
- Syntax checks for the changed main process files and `git diff --check` passed.

For each significant new defect, a test failed before the fix. Small defensive and interface changes were the exceptions. An independent review found more defects, which the project fixed. The audit used behavior tests to verify fixes.

### Editor measurements

`test/integration/editor-benchmark.cjs` opens a synthetic PNG, adds three annotations, tests 100% zoom and fit, and exports a PNG. The check compared the displayed interface and the exported image. The renderer console logged 0 errors, the panels did not overlap, and the export excluded selection handles.

| Synthetic image | Open time | PNG export and save time | Renderer RSS before export | Total Electron RSS before export |
|---|---:|---:|---:|---:|
| 1920×1080 | 226.4 ms | 951.4 ms | 125.9 MiB | 453.6 MiB |
| 3840×2160 | 196.2 ms | 114.1 ms | 143.4 MiB | 608.1 MiB |

The check took one measurement per size in sequence. The first run was cold and the second was warm. A build or update ran in parallel, and the check did not control system load. The numbers cover those runs only. Comparing sizes, measuring capture latency, setting service targets, or checking for memory leaks requires separate tests. Total resident memory (RSS) includes the runtime, the graphics process, and measurement tools.

The check wrote `<temp>/kadr-audit-visuals/editor-benchmark.json`, `editor-1920x1080-fit.png`, `editor-3840x2160-fit.png`, and `annotated-3840x2160.png`. The system may delete these temporary files. The project retains the test script and the measurements.

## Proposed work

The table includes tests and possible changes. A proposal may need further testing to confirm a defect. P1 covers the next reliability and testing work. P2 covers the following round. P3 covers new product capabilities. The project will decide the scope and interface separately.

| No. | Priority | Proposal | What to check or build |
|---:|---|---|---|
| 1 | P1 | Test with two physical displays | Test different pixel densities, negative coordinates, disconnect and reconnect, resolution changes, and full screen. Verify both the selected display and the captured pixels. |
| 2 | P1 | Test on Windows hardware | Check window, display, and scrolling capture, scaling, audio loopback, microphone, Unicode paths, installation, updates, and removal. These still need verification on Windows hardware. |
| 3 | P1 | Run tests on pushes and pull requests | The build workflow now runs manually or on a tag. Run quick Node tests, renderer smoke tests, and packaging separately. Keep failure reports. |
| 4 | P1 | Restore unsaved editor changes | Recover the base image, objects, backdrop, and document position after a crash. Replace the original only when the user saves. |
| 5 | P1 | Recover recordings with multiple audio tracks | Keep a journal of raw, system audio, microphone, and separate track files with time offsets. Recover interrupted recordings with their audio. |
| 6 | P1 | Limit the recording queue on slow disks | Promise chains can queue Blob objects faster than the disk writes them. Simulate a slow disk, cap queued bytes and wait time, and stop recording cleanly at the limit. |
| 7 | P1 | Check free disk space | Check before and during recording. Stop before the disk fills and keep the material already written. Test `ENOSPC`. |
| 8 | P1 | Limit editor memory use | Set byte limits for the base canvas, history, and assets. Release resources that the current document, Undo, and Redo can no longer reach. |
| 9 | P1 | Limit the pixel area of scrolling captures and canvases | One 6000×30000 RGBA image uses about 687 MiB. Estimate total area and peak memory while copying as well as limiting height. |
| 10 | P1 | Check whether capture includes Kadr's controls | On macOS 15 and later, test the scrolling capture panel and `contentProtection` separately. The audit did not run real capture. |
| 11 | P1 | Identify displays when older source lists omit IDs | Matching by list position does not confirm the physical display. Use a fallback that can verify the match. |
| 12 | P1 | Redact sensitive data | Add a separate opaque fill and check the exported file. Treat blur as a visual effect. Verify that redaction removes the text for good. |
| 13 | P2 | Add an editable project format | Store annotations, the backdrop, and editor state separately from the flattened PNG. Support older files and recover missing assets. |
| 14 | P2 | Include backdrop changes in Undo | Editor history now covers the base image and objects. Include changes to backdrop settings in Undo. |
| 15 | P2 | Define what Save As changes | Decide whether the copy becomes the active document. Apply that decision to the path, title, and next Save. |
| 16 | P2 | Show progress and support cancellation | Show progress for text recognition, background removal, and GIF export. Cancel cleanly and discard stale results. |
| 17 | P2 | Report why scrolling stopped and offer the partial image | If overlap, the worker, or permissions are lost, offer the part already assembled. Test scrolling up, sticky headers and footers, and repeated rows in a running renderer. |
| 18 | P2 | Test keyboard and VoiceOver access | Check focus, field names, toolbars, popovers, dialogs, the timeline, the crop slider, and shortcuts when the keyboard layout changes. Test visual and keyboard behavior. |
| 19 | P2 | Let users recover deleted library items | Add a trash folder or a short undo period, including for bulk deletes. State how long recovery is available and what it costs in disk space. |
| 20 | P2 | Handle large libraries | Add pagination or render only visible items. Measure search time on large indexes. Update one card without rebuilding the grid. |
| 21 | P2 | Validate settings | Check types, ranges, allowed values, and migrations. Valid JSON with the wrong shape must leave existing functions usable. |
| 22 | P2 | Test long synthetic recordings | Record for 30 to 60 minutes. Test pause and resume, a slow disk, and worker failure. Measure memory use, duration, and audio drift. |
| 23 | P2 | Measure real capture time | Measure shortcut to screenshot and screenshot to editor separately. Compare cold and warm starts at different pixel densities. The current measurements cover only the editor. |
| 24 | P2 | Use workers for large masks and image stitching | Measure stalls in the main process and renderer, as well as data copying. Move the expensive operations to workers and support cancellation. |
| 25 | P2 | Test difficult media files | Include variable frame rates, sample aspect ratios, multiple video or audio streams, and very short or damaged clips. Compare the preview with the export. |
| 26 | P2 | Test hardware encoding and a fallback | Check support in the bundled FFmpeg. Measure speed, quality, energy use, and file size before enabling it. |
| 27 | P2 | Sign and notarize the release | Use Developer ID, build reproducibly, and check that an update keeps system permissions. The ad hoc test package does not verify this. |
| 28 | P2 | Audit the full dependency tree regularly | Include Electron even though it is a `devDependency`. Track upstream minimatch and remove the override once electron-builder has a compatible fix. |
| 29 | P3 | Add appearance and export presets | Reuse common combinations of color, thickness, backdrop, and format. |
| 30 | P3 | Edit images in batches | Change size, format, or backdrop for multiple files with a preview. Keep the originals. |
| 31 | P3 | Add recording diagnostics | Report the source, actual dimensions, frame rate, active audio, disk status, and reason for a fallback. Exclude personal content from the exported report. |
| 32 | P3 | Queue exports in the background | Run multiple long exports independently of their windows. Define what happens on cancellation, app exit, and recovery. |

Start with hardware tests and continuous integration. Then work on recovery and memory and disk limits. Follow with editable documents, accessibility, and presets or other changes that reduce repeated steps. For the next major interface change, compare three small designs before choosing one.

## Test limits

The audit did not test two physical displays, system permissions, real desktop scrolling, long recordings with audio, sleep and wake, or Windows. It did not build the universal or Intel app or the Windows installers. The ASAR merge check covered only the merge. The temporary macOS package used ad hoc signing. The audit did not notarize or install it.

Kadr retains material from failed recordings in `recordings-tmp` in its profile. The files can take up disk space and need manual review. This version has no automatic assembly of separate tracks or recovery interface. The checks cover the scenarios described above.
