# Kadr — комплексный аудит 9 ноября 2026

## Результат и границы

Проверены функциональность, жизненный цикл захвата и записи, редакторы, сохранение/восстановление, границы IPC, зависимости, упаковка и основные направления оптимизации/UX. Подтверждённые дефекты исправлены локально. Существенный новый интерфейс или новые продуктовые функции не добавлялись.

Исходная точка аудита — коммит `7c8a889` в `main`, версия 1.0.10. Исправления аудита включены в версию 1.0.11 и перечислены в [журнале изменений](../CHANGELOG.md).

Личные изображения/записи не использовались. Проверки работают с синтетическими файлами, отдельными временными профилями, mock-устройствами и намеренно внесёнными ошибками. Рабочий стол и микрофон не записывались.

## Исправления

| Область | Подтверждённый дефект и итог |
|---|---|
| Сохранение изображений | Три параллельных сохранения с одним шаблоном имени создавали один файл. Общая очередь автоматического сохранения по реальному каталогу сохраняет все файлы; ошибка одного задания не блокирует следующее. Автосохранение захвата использует тот же атомарный путь. |
| Библиотека: аварийное завершение | PNG, записанный до отложенного сохранения индекса, не восстанавливался, если старый индекс был валидным. Неучтённые PNG теперь сверяются при каждом старте. |
| Библиотека: скрытие данных | При ошибке записи новой миниатюры оставалось старое превью. Старое превью удаляется до замены пикселей; при неудаче остаётся отсутствующее превью, которое восстанавливается из актуального PNG при следующем старте. Старый OCR очищается. |
| Библиотека: повреждённые метаданные | Независимая ревизия поймала риск новой операции восстановления: имя миниатюры могло совпасть с исходным PNG. Индекс теперь допускает только собственные `id.png`/`id.thumb.jpg`; повреждённые индексы сохраняются отдельно, оригиналы восстанавливаются. |
| Поиск | Старый асинхронный ответ мог перерисовать уже изменённый запрос и выделение. Проверяются поколение запроса и актуальный текст; ошибка текущего запроса видна пользователю. |
| Горячие клавиши | Закрытие/крах настроек во время записи сочетания оставляли глобальные клавиши выключенными. Приостановка принадлежит конкретному webContents и снимается при его завершении. Убраны устаревшие статусы конфликтов и необработанные async-ошибки действий. |
| Несохранённые изменения | Подложка и текущий ввод текста не всегда выставляли dirty до закрытия окна. Теперь выставляют сразу. Сохранение/Save As работают прямо в текстовом поле, включая русскую раскладку. |
| Удаление фона | Запоздалый результат мог заменить более новые правки. Актуальность проверяется после кодирования, native-запроса, декодирования и перед fallback. Освобождается ImageBitmap. |
| Скрытие текста/OCR | Смена базовых пикселей и undo могли оставить старые координаты OCR. Кэш и запросы привязаны к базе/объекту, устаревшие ответы игнорируются; до нового ответа закрывается вся выбранная область. |
| Copy/Save/GIF | Позднее Copy могло вернуть в библиотеку старый снимок после нового Save. Обе операции упорядочены. GIF «до/после» получает кадры одной ревизии. |
| Контуры выделения | Лимит 250000 сегментов проверялся после построения полного Path2D. Теперь построение прекращается сразу после превышения; используется прежняя рамка. На синтетической маске 1024² вместо 1048576 строится 250001 сегмент. |
| Overlay | Закрытие, крах и ошибка загрузки оставляли capture busy. Ожидания очищаются; поздняя загрузка отменённого окна не запускает захват. Смена топологии отменяет выбор по старым координатам. |
| Скролл-захват | Добавлены таймауты, привязка запросов к сессии, очистка IPC/listeners, защита повторного Finish и падения панели. Отменённая сессия не воздействует на следующую. |
| Мониторы | Известный несовпадающий display_id больше не подменяется другим экраном в screenshot/scroller/recording. В screenshot/recording сохранена совместимость полного legacy списка вообще без ID; его физический порядок остаётся ограничением. |
| Высота скролл-снимка | Лимит 150 px ранее давал 160 px из-за повторно добавленного footer. Лимит соблюдается и на первом кадре; уже заполненный первый кадр не вызывает лишней прокрутки. |
| Отмена записи | Отмена во время поиска источника, разрешения, открытия raw/stem или native audio могла запустить запись позднее либо оставить ресурс. Подготовка и освобождение принадлежат одной сессии; новый старт ждёт её завершения. |
| Ошибка старта worker | Независимая ревизия обнаружила unhandled rejection при синхронной ошибке send. Ожидание started теперь корректно завершается и в этом случае. |
| Поворот видео | Размеры импортированного видео с rotation 90°/270° теперь соответствуют отображению и кадрированию; 180° не меняет размеры. Проверено реальным FFmpeg. |
| Операции видеоредактора | Импорт мог подменить файл уже начавшемуся экспорту. Импорт/удаление/экспорт резервируют документ до первого await; закрытому окну поздний результат не применяется. |
| Сохранность аварийной записи | Ошибка probe или delivery больше не означает удаление raw/отдельного звука/готового промежуточного файла. После успешного полного сохранения обычные временные файлы очищаются. Ошибка проверки выходного файла не подменяется диагнозом EMPTY. Восстановление не перезаписывает предыдущий неудачный кандидат. |
| Зависимости | Electron 44.4.4 → 44.10.2, electron-builder 26.15.3 → 26.18.0, обновлены fast-uri/undici. Исправленный minimatch 11.0.1 ограничен уязвимыми ветками 7–10; старые callable API 3/5 сохранены. |

Отдельный набор сохранности аварийной записи: 9/9 сценариев, включая штатную успешную очистку, ошибки чтения/записи/смешивания звука и частичную запись первого chunk при ENOSPC. Последний случай найден независимой ревизией: счётчик полностью записанных байтов равнялся нулю, хотя файл уже содержал данные. Такой файл больше не удаляется.

- Реальный FFmpeg: аудиодорожки/кодеки, отмена экспорта и ролики с rotation 90/180/270, кадрирование/изменение размера — проходят в общем наборе.
- Вызов скрипта native-сборки подтвердил актуальный ранее собранный universal helper; Swift-код в этом аудите не менялся. Это не новый полный compile native helper.
- Полный `npm audit`: 0 известных уязвимостей. Первоначально было 9 затронутых пакетов (2 high, 7 moderate). Проверять только `--omit=dev` недостаточно: Electron объявлен devDependency, но входит в приложение.
- `npm ls` проверил согласованность зависимостей. Независимо проверены реальные FileMatcher include/exclude/partial/extglob и synthetic mergeASARs allow/deny для нового minimatch; legacy glob/asar/filelist оставлены со старым API.

Native helper и ru/en tessdata присутствуют. Нотаризация не выполнялась. Это проверочный пакет, не опубликованный релиз.
- Синтаксические проверки изменённых main-файлов и `git diff --check` — прошли.

Все новые важные дефекты подтверждались падающими тестами до исправления, кроме простых защитных/UX дополнений. При независимой ревизии обнаружены и устранены дополнительные дефекты; сборка сама по себе не использовалась как доказательство поведения.

### Диагностические измерения редактора

Повторяемый сценарий: `test/integration/editor-benchmark.cjs`. Искусственный PNG, три аннотации, zoom 100%/fit, PNG export, визуальная проверка UI и изображения. Ошибок renderer console: 0; панели не перекрываются, handles выделения не попадают в экспорт.

Это не сравнение скоростей размеров, не SLA, не задержка реального захвата и не доказательство отсутствия утечки. Общий RSS включает runtime/GPU/инструментализацию.

## Ограничения результата

Физические два монитора, системные разрешения, настоящий desktop-scroll, длинная запись со звуком, sleep/wake и Windows в этой задаче не проверялись. Universal/Intel приложение и Windows установщики не собирались; тест ASAR merge не заменяет universal build. Временный пакет ad-hoc, без нотарификации и установки. Сохранённые после ошибок материалы остаются в `recordings-tmp` внутри профиля Kadr; они требуют отдельного разбора, могут занимать место, автоматический монтаж всех дорожек и UI восстановления не добавлены. Новая логика протестирована в описанных границах; отсутствие найденных ошибок не является доказательством их полного отсутствия.

## Источники и существенные попытки

- Исходники и регрессионные тесты в репозитории.
- Логи общих тестов и npm audit в `<temp>/kadr-audit-*`; воспроизводимые команды перечислены выше.
- [Electron: блокировка скомпрометированных сертификатов](https://github.com/electron/electron/security/advisories/GHSA-jr5w-w6x2-84p9).
- [minimatch: усиление сложности glob-паттерна](https://github.com/isaacs/minimatch/security/advisories/GHSA-g3hv-75wg-m249).
- В sandbox GUI завершался SIGABRT, npm не разрешал DNS. Разрешённые повторные запуски вне sandbox работали; профиль оставался временным.
- GitHub дважды ответил 504 при загрузке Electron/иконок сборщика. Проверка официального архива дала 200; после повторной загрузки runtime и сборка прошли.
- Начальный слишком широкий override minimatch затрагивал старые API; он заменён селектором версий 7–10. Итоговые npm ls/audit и реальная упаковка прошли. Понижение сборщика через `audit fix --force` не применялось.
- Первая сверка упаковки включила служебный `.DS_Store`, который корректно исключён сборщиком; сверка всех 130 отслеживаемых файлов src прошла.
